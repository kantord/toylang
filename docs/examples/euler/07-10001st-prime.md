# The ten-thousand-first prime

Solves [Project Euler 7](https://projecteuler.net/problem=7). See the
[spoiler warning](00-spoiler-warning.md).

There is no lazy, open-ended generation of primes: a `Stream` is born only at `inputs` or
`lines`, not at a synthetic source like `range`. So this picks a fixed upper bound known to
hold the ten-thousand-first prime, tests every candidate up to it, and indexes into the result instead of
stopping early. `has_divisor` checks 2 and then only odd divisors, since nothing past 2 can be
even.

```toylang
fn has_divisor(p: {n: Int, d: Int}) -> Int =
    0 if p.d * p.d > p.n else
        1 if p.n % p.d == 0 else
        has_divisor({n: p.n, d: p.d + (1 if p.d == 2 else 2)})

fn is_prime(n: Int) -> Int =
    0 if n < 2 else 0 if has_divisor({n: n, d: 2}) == 1 else 1

(collect(range(104744)) | select(is_prime(.) == 1))[10000]!
```

```output
104743
```

The jq backend is the outlier here: trial division over 100,000-odd candidates takes it
several seconds, against a fraction of a second for the compiled and JIT backends. Everyone
still agrees; it is just slow, not a wall.
