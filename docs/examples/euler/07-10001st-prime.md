# The ten-thousand-first prime

Solves [Project Euler 7](https://projecteuler.net/problem=7). See the
[spoiler warning](00-spoiler-warning.md).

There is no open-ended generation of primes: `range` is a stream, but a bounded one, and
nothing cuts a stream at its ten-thousand-first hit. So this picks a fixed upper bound known
to hold the ten-thousand-first prime, tests every candidate up to it, and indexes into the
result instead of stopping early. `has_divisor` checks 2 and then only odd divisors, since
nothing past 2 can be even; `and` and `or` short-circuit, so the recursion ends at the first
divisor found, or once the divisor's square passes `n`.

```toylang
fn has_divisor({ n, d }: { n: Int, d: Int }) -> Bool =
  d * d <= n and
    (
      n % d == 0 or
        has_divisor { n: n, d: d + (d == 2 | . -> 1 or 2) }
    )

fn is_prime(n: Int) -> Bool =
  n >= 2 and not has_divisor { n: n, d: 2 }

(collect(range 104744) | select is_prime(.))[10000]!
```

```output
104743
```

The jq backend is the outlier here: trial division over 100,000-odd candidates takes it
several seconds, against a fraction of a second for the compiled and JIT backends. Everyone
still agrees; it is just slow, not a wall.
