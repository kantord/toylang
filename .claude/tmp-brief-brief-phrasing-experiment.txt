Maintainer note (composed 2026-08-31): generic non-informational reassurance phrasing (example
given: "its much simpler than you think") in dispatch briefs seems to help planning agents find
better plans. The maintainer wants this tested on at least 10 issues, with progress reported and
a grilling round on the results.

dispatch and observe 10 real lane builds inside this single session. Your deliverable is the
scaffolding that lets the coordinator (the recurring drive tick) actually run that experiment
over the next 10+ dispatches, plus a place to record results:

1. Read plans/opencode-rollout.md for full context (search "brief-phrasing-experiment" and
   "reassurance phrasing") and read how briefs currently get composed and handed to
   .claude/scripts/sandbox_dispatch.py (check the enwiro-delegate skill and the drive skill for
   the brief-writing step).
2. Design a minimal, low-friction way for the coordinator to A/B this on future briefs -- e.g. a
   convention (a marker line in the brief file, or a coin-flip the coordinator performs and notes
   in its board commit message) that tags each dispatched brief as "reassurance: yes/no", plus a
   tracking log (a new plans/brief-phrasing-experiment.md is fine) where each of the next 10+
   dispatches gets one row: lane id, reassurance yes/no, outcome (landed clean / land-failed /
   commitless run / escalated), and a one-line note on plan quality if visible from the sandbox
   log.
3. Seed that tracking file with a short methodology section (what "reassurance phrasing" means
   operationally, so future ticks apply it consistently) and an empty results table ready for the

   is itself scripted (check first; don't assume).
5. Commit the tracking file and methodology note. There is no code change to land here beyond
