Task: make `.claude/scripts/land_lane.py` land a dispatch patch whose only stale part is a GENERATED file, instead of failing the whole land. Edit only `.claude/scripts/land_lane.py` and add a test under `.claude/scripts/tests/`.

Problem (evidence, 2026-09-19). `cmd_land_patch` (grep -n "def cmd_land_patch") applies the dispatch patch with `git am` onto current main. Two GREEN patches (select-lazy-materialization-build-js and -lua) each touch `site/public/corpus.json`. That file is generated, and main rewrites it on nearly every landing, so `git am` refuses with `patch failed: site/public/corpus.json:14`. Each failure runs `retrigger()`; after 3-4 attempts the retry cap is spent and a `land-failed-*` marker is left. The agent's real edits (src/emit_js.rs, snapshots) were fine. A generated file must never be able to fail a landing.

The file already knows which paths are generated: the `GENERATED` set and `REGEN_TESTS` near the top, and the regeneration block inside `land_one` (grep -n "generated files only"). That block is the pattern to reuse.

Required change:
1. In `cmd_land_patch`, apply the patch with one `--exclude=<path>` argument per entry of `GENERATED`: `git am --exclude=site/public/corpus.json --exclude=... <patch>`. `git am` passes `--exclude` to `git apply`. Excluded hunks are dropped, so a stale generated hunk cannot conflict.
2. After a successful `am`, and before calling `land_one(n)`, regenerate the generated files in the lane worktree `d`: run `cargo nextest run -E REGEN_TESTS` (twice, as the existing block does: once to write, `cargo insta accept`, once to verify), then `git add` the GENERATED paths and, only if `git diff --cached --quiet` reports a change, commit them with a message like `Regenerate generated files for gh:<n>`. If the verify run is red, `retrigger(n, "generated-file regeneration failed", log)` and return 1, same as the existing regeneration-failed path.
3. Factor the regenerate-and-verify sequence into one helper used by both this new path and the existing conflict block in `land_one`, so there is a single copy. Do not change the behaviour of the existing conflict path.
4. A patch that fails `am` for a NON-generated reason must still go through `retrigger` exactly as today.
5. Add a test in `.claude/scripts/tests/` (look at test_dispatch_observability.py for the style; a plain pytest file). Build a throwaway git repo in a tmp dir with a `site/public/corpus.json`, make a patch that edits that file plus another file, advance the repo so the corpus.json hunk no longer applies, and assert that the `am` invocation used by `cmd_land_patch` succeeds and leaves the other file's change applied and corpus.json equal to the base copy. Factor the `am` call into a small function (for example `apply_patch_excluding_generated(d, patch_file, log) -> bool`) so the test can call it without cargo.

Done-gate: `just check` stays green and the new test passes with `python3 -m pytest .claude/scripts/tests` (or `uv run --project .claude/scripts pytest`). Do not run the full landing.
