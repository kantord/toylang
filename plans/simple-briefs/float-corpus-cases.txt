## Background (why this matters)

Float (IEEE binary64 per docs/adr/0007-float-is-javascript-double.md) already has per-backend
tests in `tests/backend_go.rs`, `tests/backend_python.rs`, `tests/backend_rust.rs`,
`tests/backend_lua.rs` (check which backend test files actually have Float cases -- grep for
`float` case-insensitively across `tests/backend_*.rs`). Those tests only run one backend each; the
project's real cross-backend agreement check lives in `tests/corpus/*.yaml` (see
`tests/corpus/input_annotation.yaml` for the shape of a corpus case: a `.tl` source snippet plus
expected output, run through all seven backends and required to agree byte for byte). Float has no
corpus case, so the seven-backend agreement check does not cover it at all -- only whichever
backends happen to have their own one-off test file.

This was flagged in `float-build-c-escalation` (see `plans/board-archive.yaml` for that row's
history) as still needing "Go/Python/Rust/Lua before it can be a corpus case" -- all four have since
landed, but nobody filed the corpus-promotion follow-up until the 2026-09-18 status audit
(`plans/status-audit-2026-09-18.md`) caught the gap.
