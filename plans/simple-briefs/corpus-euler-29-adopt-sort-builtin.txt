## Why this row exists

`sort(v: Vec<Int>|Vec<Int64>|Vec<Str>|Vec<Char>) -> Vec<...>` and `sum(v: Vec<Int>) -> Int` are
real builtins today (confirmed: `src/tags.rs:187,189` define `Builtin::Sort`/`Builtin::Sum`, every
backend emitter implements both, e.g. `src/emit_rs.rs:1532` `tl_sort(&...)`, `tests/reductions.rs`

doc's current prose still cites gh:86 as a missing feature and works around it with a hand-rolled
`is_dup`/`distinct_count` doing an O(n^2) earlier-element scan, only kept fast enough by
restricting it to the (at most 6) roots that have more than one power in range. `sort` makes
distinct-counting the *entire* 9801-key set directly tractable, so that whole restriction
structure (`is_primitive`, `single_contrib`, `multi_contribs`, `multi_root_contribution`,
`exponents_for_root`, `row_for_j`, `powers_of`, `powers_from`) is no longer needed -- not just
`is_dup`/`distinct_count`.

## Target rewrite

Replace everything from `is_dup` through `solve` (current lines 48-90) with a direct build of all
9801 `(a, b)` keys, one `sort`, and a run-count via `sum` over adjacent-equal indicators:

```toylang
fn key_for(p: {a: Int, b: Int}) -> Int =
    root_and_mult(p.a) | .root * 1000 + .mult * p.b

fn keys_for_a(p: {a: Int, top: Int}) -> Vec<Int> =
    collect(range(p.top - 1)) | map(. + 2) | map(key_for({a: p.a, b: .}))

fn all_keys(top: Int) -> Vec<Int> =
    flatten(collect(range(top - 1)) | map(. + 2) | map(keys_for_a({a: ., top: top})))

fn is_adjacent_dup(p: {v: Vec<Int>, i: Int}) -> Int =
    p | p.v[p.i + 1]! == p.v[p.i]! -> 1 or 0

fn adjacent_dup_count(sorted: Vec<Int>) -> Int =
    sum(collect(range(length(sorted) - 1)) | map(is_adjacent_dup({v: sorted, i: .})))

fn distinct_count(v: Vec<Int>) -> Int =
    length(v) - adjacent_dup_count(sort(v))

fn solve(top: Int) -> Int = distinct_count(all_keys(top))

solve(100)
```
