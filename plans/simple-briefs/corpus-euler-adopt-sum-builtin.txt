before `sum` was available.

`sum(v)` is `Vec<Int> -> Int` and `Vec<Int64> -> Int64` (an empty `Vec` sums to `0`, no `Opt`
wrapping needed, unlike `max`). Several of these pages chunk or halve their recursion purely to
keep a hand-rolled fold's call-stack depth shallow on every backend -- since `sum` is a builtin
reduction (not user-space recursion), that depth concern goes away once `sum` does the reducing,
so the chunking/halving helpers can usually be deleted outright, not just renamed.

Edit these five files. Each is a real `.toylang` fragment inside a fenced code block in a prose
`.md` page -- keep the prose accurate to the new code (drop sentences that describe a helper you
delete, and correct any recursion-depth justification that no longer applies) and keep the
`output`/`input` fenced blocks unchanged.

## docs/examples/euler/13-large-sum.md

Delete `col_sum` (the recursive per-row fold over one digit column). Replace its one call site in
`column_total` with `sum`, mapping each row to its digit at column `k`:

```toylang
fn column_total(p: {nums: Vec<Vec<Int>>, k: Int, carry: Int}) -> Int =
    sum(p.nums | map(.[p.k]!)) + p.carry
```

Everything else (`empty`, `emit_carry`, `add_digits`, `first_ten`, `leading_digits`) stays as-is.
Update the prose sentence describing `col_sum` (currently "adds one column of digits at a time
