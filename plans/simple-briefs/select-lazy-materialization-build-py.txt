## What's different about Python here (read this first)

Unlike Go/JS, there is currently no `tl_select`-style helper function at all -- `Kind::Select` is
emitted as an inline list comprehension at `src/emit_py.rs:634-644`:
```python
[p for p in source if pred]
```
(the codegen builds this as `format!("[{p} for {p} in {} if {}]", expr(source), expr(pred))`).
That comprehension is eager -- it runs to completion the moment it's evaluated. You're replacing
it with a lazy object.

## Design: a class with `__iter__`/`__len__`/`__getitem__`, not per-consumer wiring

Python lets an object act "list-like" everywhere (`for x in v`, `len(v)`, `v[i]`, unpacking,
passing to another comprehension) just by implementing those three dunder methods. Route them all
through the SAME densify-on-first-use logic, so every consumer that isn't the hot indexing path
works automatically without you having to find and touch it:

```python
class TlSel:
    __slots__ = ("src", "pred", "idx", "dense")

    def __init__(self, src, pred):
        self.src = src
        self.pred = pred
        self.idx = None
        self.dense = None

    def _build(self):
        if self.idx is None:
            self.idx = [i for i, e in enumerate(self.src) if self.pred(e)]

    def _densify(self):
        if self.dense is None:
            self._build()
            self.dense = [self.src[i] for i in self.idx]
        return self.dense

    def __len__(self):
        self._build()
        return len(self.idx)

    def __iter__(self):
        return iter(self._densify())

    def __getitem__(self, key):
        return self._densify()[key]
```

Change the `Kind::Select` codegen to emit `TlSel(source, lambda p: pred)` instead of the inline
comprehension (keep the same `local(*param)` name for the lambda's parameter, matching the
existing `p` naming in that code).

## The one consumer that needs an explicit fast path: `tl_at`

`tl_at` (`src/emit_py.rs:139-149`) is the O(1)-index win this row is for -- give it an explicit
branch so indexing a Select doesn't force a full `_densify()`:
```python
def tl_at(v, i, depth):
    if depth > 0:
        return [tl_at(e, i, depth - 1) for e in v]
    if isinstance(v, TlSel):
        v._build()
        n = len(v.idx)
        if i < 0:
            i = n + i
        if i < 0 or i >= n:
            return "none"
        return {"some": v.src[v.idx[i]]}
    n = len(v)
    if i < 0:
        i = n + i
    if i < 0 or i >= n:
        return "none"
    return {"some": v[i]}
```

## Everything else

`tl_slice` (`src/emit_py.rs:152-156`), any list comprehension consuming a Select's result
(`Kind::Map`/`Kind::OptMap` etc.), printing, and any other place that iterates/indexes/measures a
Select's output should work unchanged via `__iter__`/`__getitem__`/`__len__` -- verify this is
actually true for this codebase's specific consumers rather than assuming it (e.g. if the printer
does an `isinstance(v, list)` check anywhere instead of duck-typing, that would need its own
branch -- grep for `isinstance` near print/serialize codegen to check). The in-place/reuse
optimization (reusing the source's backing storage when uniquely referenced) that the shared spec
mentions is a perf nicety, not required for this row's done-gate -- skip it; always allocating a
fresh list in `_densify()` is correct and acceptable.
