## What exists today (eager, what you're replacing)

Unlike the Go/JS/Lua backends, Python has no standalone `tl_select`-style helper function --
`Kind::Select` is emitted as an inline list comprehension at `src/emit_py.rs:634-642`:

```rust
Kind::Select {
    source,
    param,
    pred,
} => {
    let p = local(*param);
    format!(
        "[{p} for {p} in {} if {}]",
        expr(enums, source),
        expr(enums, pred)
    )
}
```

This eagerly builds a new `list` before anyone asks for an element. There is no existing
`SELECT_HELPER`-style constant or conditional-inclusion registration to model this on directly
within `emit_py.rs`'s own Select path -- `src/emit_py.rs:224` (`SUM_HELPER`) and its registration
at `src/emit_py.rs:365` are this file's precedent for how a *named* runtime helper is defined and
conditionally included, which you will need since a lazy representation can no longer be a bare
comprehension.

## What to build instead

Replace the inline comprehension with a call to a new runtime helper (following the
`SUM_HELPER`/`uses("tl_sum(")` naming and registration precedent) that builds a mask/selection
representation once (O(n) over the mask), then gives O(1) indexed access into it without copying
filtered elements out yet. Compact (materialize a real `list`) only on the first strong
(non-transient) reference -- reusing the source's underlying list in place if the source is
uniquely referenced at that point, copying otherwise. This mirrors the same provably-one-reference
condition `mutation-semantics-spike` (`plans/mutation-semantics-spike.md`, "(2) Is the rule
decidable from the current TIR?") already established for fused-loop/copy-elision: a name with
exactly one use, that use consuming, no use following it -- decidable from a TIR occurrence-count
scope walk, no borrow checker, no runtime refcounting.

Do NOT change `Kind::Select`'s AST/checker shape or its observable semantics -- `xs | select(pred)`
must keep producing the exact same elements in the exact same order as today. This is purely a
change to how the Python backend *represents* the result between the `select` call and whatever
consumes it next (indexing, iteration, another pipe stage, printing, etc.).
