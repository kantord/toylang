## What exists today (eager, what you're replacing)

`src/emit_lua.rs:15-22`:

```lua
local function tl_select(src, pred)
  local out = {}
  for i = 1, #src do
    if pred(src[i]) then out[#out + 1] = src[i] end
  end
  return out
end
```

Today, `tl_select` walks the source once and eagerly builds a new, shorter table before anyone
asks for an element.

## What to build instead

Replace the eager filter with a lazily-built selection: build a mask/selection-vector once (O(n)
over the mask bits), then give O(1) indexed access into it without copying the filtered elements
out yet. Compact (materialize a real table) only on the first strong (non-transient) reference --
reusing the source's underlying table in place if the source is uniquely referenced at that point,
copying otherwise. This mirrors the same provably-one-reference condition
`mutation-semantics-spike` (`plans/mutation-semantics-spike.md`, "(2) Is the rule decidable from
the current TIR?") already established for fused-loop/copy-elision: a name with exactly one use,
that use consuming, no use following it -- decidable from a TIR occurrence-count scope walk, no
borrow checker, no runtime refcounting.

Do NOT change `Kind::Select`'s AST/checker shape or its observable semantics -- `xs | select(pred)`
must keep producing the exact same elements in the exact same order as today. This is purely a
change to how the Lua backend *represents* the result between the `select` call and whatever
consumes it next (indexing, iteration, another pipe stage, etc.). Note Lua tables are 1-indexed
and use `#src`/`nil`-terminated length semantics -- keep your lazy representation consistent with
how this file's other helpers (e.g. `tl_map`, `tl_field`) already handle Lua table indexing.

Per-backend builtin-wiring precedent to follow (naming/registration convention):
`src/emit_lua.rs:209` (`SUM_HELPER`, registered the same way `SELECT_HELPER` is, at
`src/emit_lua.rs:561`).

## Ruled pattern (2026-09-19, select-lazy-materialization-convergence-ruling, option a)

Mirror Python's landed lazy Select: read `src/emit_py.rs` lines 137-184 (`TLSEL_HELPER`, class
`TlSel`: src/pred/idx/dense, `_build` computes survivor indices once, `_densify` builds the real

densify for every consumer that iterates or slices). Any consumer you do not make lazy must call
the densify path -- always correct. Skip in-place reuse. Read the Go/JS sibling briefs' lessons:
after `just check` shows expected snapshot diffs, accept them with `cargo insta accept` (never
hand-edit `.snap`), rerun `just check` to green.
