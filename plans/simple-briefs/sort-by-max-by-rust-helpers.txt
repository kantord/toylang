The reference semantics already landed in the Go backend (commit `1456d9f`, `src/emit_go.rs`):
`tlSortBy` is a *stable* sort by a projected key (Go uses `slices.SortStableFunc` because
`slices.Sort` isn't guaranteed stable); `tlMaxBy` folds over the slice keeping the first element
on ties (`key(x) > key(m)`, strictly greater, so an equal key does not replace the current max).

Concretely, add two new `const` string helpers to `src/emit_rs.rs`, placed near the existing
`SORT_HELPER`/`MAX_HELPER`:

1. `TL_SORT_BY_HELPER` (or similar name matching this file's existing naming convention) --
   `fn tl_sort_by<T: Clone, K: Ord>(v: &[T], key: impl Fn(&T) -> K) -> Vec<T>` that stable-sorts
   a cloned copy of `v` by the projected key. Rust's `slice::sort_by_key` is already stable, so
   `out.sort_by_key(|x| key(x)); out` (or `sort_by(|a, b| key(a).cmp(&key(b)))`) is sufficient --
   no need for Go's stable-sort workaround since Rust's default is already stable.

2. `TL_MAX_BY_HELPER` (or similar) -- `fn tl_max_by<T: Clone, K: Ord>(v: &[T], key: impl Fn(&T)
   -> K) -> Option<T>` that returns the first element with the maximum projected key on ties
   (mirror the Go fold: only replace the running max on strictly-greater key, never on equal).
