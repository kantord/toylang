# The corpus, browsable

Every program in `tests/corpus/`, the code each of the six backends compiles it to, and the
JavaScript one running in the page against input you can edit.

## Running it

```
pnpm install
pnpm dev
```

`pnpm check` typechecks and then runs every case through the browser's copy of the JavaScript
runner, comparing against the recorded output. `pnpm build` produces `dist/`.

## Where the data comes from

`public/corpus.json` is generated by `cargo test --test export_site` from the repository root,
which walks the same corpus the agreement harness does and asks every backend to emit. It is
committed, so the site builds without a Rust toolchain -- and because a committed artifact can
fall behind, `pnpm check` fails if the case names in it no longer match `tests/corpus/`.

Regenerate it after adding or changing a case:

```
cargo test --test export_site
```

## Running the emitted JavaScript

The emitted code is written for node: it reads stdin through `require("fs")` and prints with
`console.log`. `src/lib/run-js.ts` supplies both as arguments rather than rewriting the code to
suit a browser, so what runs is exactly what the JavaScript tab shows. That is the point of the
check: a shim that drifts from node would make the tab a lie.
